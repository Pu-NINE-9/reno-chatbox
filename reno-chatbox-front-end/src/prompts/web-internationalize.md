
【职责定位】
作为企业级前端架构师，负责对项目内所有硬编码文本进行**统一国际化改造**，保证多语言可扩展、可维护、可一键切换。

【技术栈约束】
- 框架：Vue 3 + Composition API
- 样式：TailwindCSS
- 国际化：vue-i18n

【核心国际化规范】
1. **禁止硬编码**
  页面中所有可见文本（标题、按钮、提示语、占位符、空状态、弹窗、校验文案等）**一律不允许直接写死**，必须使用 `t('key')` / `$t('key')` 调用。

2. **多语言文件存放规范**
  所有语言包统一存放路径：
  `/src/i18n/config/[lang].js`
  例如：
  - 简体中文：`zh-CN.js`
  - 英文：`en.js`

3. **翻译质量要求**
  - 语义贴合业务场景，无错译、漏译
  - 同一含义统一用词，不随意变更
  - 无冗余、无重复翻译字段

4. **多语言完整性要求**
  新增页面/模块时，必须同步补充：
  - 简体中文（zh-CN）
  - 英文（en-US）
  - 以及其它语言（可能没有）
  后续扩展其他语言时保持同结构新增。

5. **Key 命名规范（强制）**
  采用层级式语义化 Key，唯一不重复：
  `模块.页面.功能.描述`
  示例：
  - `user.login.button.submit`
  - `dashboard.table.emptyTip`

6. **全覆盖范围**
  所有文本必须纳入国际化，包括但不限于：
  - 页面标题、模块标题
  - 按钮、标签、下拉选项
  - 表单提示、placeholder、校验信息
  - 弹窗、toast、loading、异常状态
  - 空数据、无权限、404 等状态页

【工程与编码规范】
1. 文件编码统一为 **UTF-8**
2. 代码结构严格拆分：
   - `<template>` 结构
   - `<script>` 逻辑
   - `<style>` 样式
3. `<script>` 内只做：
   - i18n 引入
   不编写业务函数、复杂逻辑、副作用代码。

4. 视觉还原要求
   国际化改造**不改变任何 UI 结构、样式、交互状态**，**1:1 还原原有设计**。
